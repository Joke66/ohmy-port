# OhmyPort 设计文档（总设计）

> 本文档从 wpf 分支现有代码倒推而来，作为单一真相源指导后续迭代。与源码不一致时，以「先改文档、再改代码」原则回填。
> 分模块细节见子设计文档：`子设计-Core逻辑层.md`、`子设计-App界面层.md`；接口契约见 `接口文档.md`。

## 1. 定位与目标

- 产品：Windows 串口调试助手，替代 Python + PySide6 原版的 C# / WPF 重写分支。
- 目标：功能与原版对齐，用原生 Windows 运行时（.NET 10 自包含）换取更小体积与更快冷启动（单文件 67 MB、冷启 ~1.6s）。
- 边界：只做串口调试常用能力，不做脚本引擎、不做插件体系（保持「最好用但不臃肿」）。

## 2. 技术栈选型

- 语言/运行时：C# 12+、.NET 10（`net10.0-windows`）。
- UI：WPF（`UseWPF`）+ WinForms（托盘 NotifyIcon、目录选择 FolderBrowserDialog）。
- 日志控件：AvalonEdit 6.3.1（虚拟化渲染，支撑 5 万行）。
- 串口：`System.IO.Ports` 11.0；端口友好名：`System.Management`（WMI）；编码：`System.Text.Encoding.CodePages`（GBK）。
- 配置序列化：`System.Text.Json`（snake_case、忽略注释、容忍尾逗号）。
- 测试：xUnit 2.9 + Microsoft.NET.Test.Sdk 17.14。

## 3. 工程结构

```
OhmyPort.sln
├── src/OhmyPort.Core/       逻辑层（无 UI，可单测）
├── src/OhmyPort.App/        界面层（WPF）
└── tests/OhmyPort.Core.Tests/  xUnit 单测
```

依赖方向：`App → Core`（单向），`Tests → Core`（单向）。Core 不得反向引用 App 或任何 WPF/WinForms 类型。

## 4. 线程模型

```
┌──────────────────── 每个 SessionView 一份 ────────────────────┐
│  SerialMonitor.ReceiveLoop（后台线程）                          │
│    读串口 → 按行(SplitLines)或按帧(FrameParser.Feed)切分        │
│      → Received 事件（在接收线程上）                            │
└──────────────────────────┬────────────────────────────────────┘
                           ▼
        SessionView.OnReceived → ConcurrentQueue<LogRecord>（线程安全边界）
                           ▼
        DispatcherTimer.Flush（UI 线程，80ms 一批）
          写文件(LogManager) + 过滤(LogFilter) + 格式化(FormatLine)
                           ▼
        LogView.AppendLines（AvalonEdit 批量插入 + MaxLines 裁剪 + 自动滚底）
```

- 串口接收线程与 UI 线程之间唯一的数据边界是 `ConcurrentQueue<LogRecord>`。
- 暂停 `_paused` 只冻结 rx/tx 显示，接收与缓冲不停；恢复时 `ReRender()` 从 `_buffer`（上限 `UiDefaults.MaxLines=50000`）全量重建。
- 定时循环发送由 `MainWindow._cycleTimer`（DispatcherTimer）驱动，逐个取 `Cycle=true` 的命令发给当前活动会话。

## 5. 数据流

### 5.1 接收数据流

串口字节 → `ReceiveLoop` 读 4096 字节块 → 分帧/分行 → `Frame(Data, ChecksumOk)` → `OnReceived` 入队 → `Flush` 出队 → 三路分流：

1. 落盘：`LogManager.Write`（固定文本形式，不受 HEX 显示/过滤影响）。
2. 显示：`LogFilter.Visible` 判定 → `FormatLine` → 主日志区 `LogText`。
3. 分栏（split 模式）：`LogFilter.Matched` 命中 → 命中分栏 `MatchedText`。

### 5.2 发送数据流

输入文本 → `SendCodec.ParseHex`（HEX 模式）或 `ParseEscaped`+追加换行（文本模式）→ `SerialMonitor.Send` → 成功后入队一条 `Tx` 记录（回显到日志区并计入 `_txBytes`）。

### 5.3 配置数据流

启动 `ConfigService.Load` → `AppConfig.Normalize` 裁剪 → 注入 `MainWindow`/各 `SessionView`；关闭 `SaveConfig` 从会话回读状态写回 `serial_tool_config.json`。

## 6. 模块职责划分

- `OhmyPort.Core`：纯逻辑，无 UI 依赖，全部可单测。含串口后端、帧协议、编解码、过滤、配置、日志落盘、文本/数值工具。
- `OhmyPort.App`：主窗口编排（会话管理/菜单/工具栏/发送辅助/配置导入导出/托盘/背景）、会话视图、日志控件、主题系统、各类对话框。

## 7. 关键设计决策

- 配置 JSON 字段沿用旧版 snake_case，保证老配置直接可读（见接口文档）。
- 日志控件选 AvalonEdit 而非 TextBox，解决 5 万行实时追加的性能问题（实测批量追加 133ms、实时 40 行/批 0.04ms）。
- 主题用「[0] 主题字典 + [1] Base.xaml 控件样式」的 MergedDictionaries 约定切换；背景皮肤通过把大面积容器画刷换半透明实现（`ThemeService.SetSurfaceTranslucency`）。
- 托盘用 WinForms NotifyIcon（WPF 无内置托盘），并抑制 WFO0003 警告。
- 帧协议解析（`FrameParser`）与数值绘图规则（`PlotRule`）已在 Core 层实现，但 UI 尚未接线（见子设计文档「待接线」小节），属后续里程碑（M6/M7）。
